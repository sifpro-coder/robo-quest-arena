# CFI Academy V3 — installation sécurisée sur Render + Supabase

## Chnoua fiha?
- **CFI Arena** تبقى تخدم: 10 لاعبين، Quiz Live، مواجهات.
- **CFI Academy** جديدة على `/academy`، بالدارجة التونسية مع المصطلحات الفرنسية في سطور مستقلة.
- 7 دروس ESP32 و15 TP من الملفات الأصلية، بصورها وأمثلتها.
- حساب Admin واحد (Prof) في قاعدة البيانات؛ التلميذ ما ينجمش يعمل Admin.
- إنشاء حسابات تلامذة من لوحة الأستاذ، كلمات مرور مؤقتة، إجبار تغيير كلمة المرور.
- QCM /20 يتصحّح من السيرفر، مع حفظ الكود والنتائج في Supabase.
- شهادة إتمام المسار الرقمي ESP32 بشرط ≥ 12/20 في كل وحدة وكتابة كود الـ15 TP؛ **التجربة الحقيقية للدارة تبقى تحت مراجعة الأستاذ**.
- إضافة دروس جديدة مباشرة من لوحة الإدارة.

## 1. ارفع ملفات النسخة إلى GitHub

1. افتح GitHub repository: `sifpro-coder/robo-quest-arena`.
2. **فك ZIP على التليفون أولًا**. ارفع هذه الملفات إلى جذر المستودع (بدون مجلّد إضافي):
   - `index.html`, `academy.html`, `server.js`, `academy-api.js`
   - `questions.json`, `academy-content.json`, `academy-bank.json`, `academy-solutions.json`
   - `logo-cfi.jpg`, `package.json`
3. يمكنك رفع `schema.sql` و`README_CFI_TUNISIE.md` للمرجع (لا يحتويان على أسرار).
4. `Commit changes` ثم انتظر Deploy في Render.
5. اللعبة تبقى على `/` والأكاديمية على `/academy`.

**مهم**: حتى لو رفعت الملفات، حسابات الأستاذ والتلامذة لن تعمل قبل الخطوتين 2 و3. هكذا نمنع حسابات تجريبية غير آمنة من الوصول إلى بيانات الأطفال.

## 2. أنشئ قاعدة بيانات Supabase مجانية

1. افتح https://supabase.com/dashboard وأنشئ مشروعًا جديدًا على خطة **Free**.
2. افتح **SQL Editor → New query** وانسخ كل محتوى `schema.sql`، ثم اضغط **Run**.
3. من **Project Settings / API Keys** خذ:
   - Project URL: `https://...supabase.co`
   - **Secret key** من نوع `sb_secret_...` (أو المفتاح legacy service_role إن مازال متاح).
4. **لا ترفع المفتاح إلى GitHub ولا ترسله في المحادثة، ولا تضعه في HTML.**

## 3. إعدادات Environment في Render

افتح Render → سيرفر CFI الحالي → Environment وأضف:

| KEY | VALUE |
|---|---|
| `SUPABASE_URL` | Project URL من Supabase |
| `SUPABASE_SECRET_KEY` | المفتاح السري `sb_secret_...` من Supabase |
| `SESSION_SECRET` | سلسلة عشوائية سرية لا تقل عن 32 حرفًا (استعمل Generate في Render إن متاحًا) |
| `ADMIN_USERNAME` | `cfi-admin` أو اسم Admin لاتيني فريد تختاره |
| `ADMIN_PASSWORD` | كلمة سر قوية **تختارها أنت بنفسك**، 12 حرفًا على الأقل |

**كلمة سر Admin ما تحطّهاش في GitHub أو ChatGPT**. تتخزن كمتغير سرّي في Render وتتحوّل في قاعدة البيانات إلى hash عند أول Login. إذا بدّلت كلمة السر من واجهة CFI، البرنامج ما يعاودش يبدلها آليًا عند النشر.

اضغط **Save / Deploy** وراجع Events حتى تظهر Live.

## 4. أوّل دخول

1. افتح `https://<YOUR-SERVICE>.onrender.com/academy`.
2. اضغط **دخول** وادخل بـ`ADMIN_USERNAME` و`ADMIN_PASSWORD` اللي اخترتهم.
3. تفتح **لوحة Admin** فقط ليك. افتح «تلميذ جديد»؛ حط Username واسم/لقب دراسي.
4. البرنامج يولّد **كلمة سرّ مؤقتة عشوائية** تظهر مرة واحدة. انقلها للتلميذ في قناة خاصة.
5. التلميذ يدخل بحسابه ويبدّل كلمة السر المؤقتة قبل ما يبدا الدروس.
6. بعد أي QCM، يشوف النتيجة مباشرة؛ أنت تشوفها من لوحة الإدارة، مع الكود والملاحظات.

## 5. الشهادات والتقييم

- تصحيح الـQCM حقيقي ومن السيرفر؛ إجابات QCM الصحيحة مخزونة في `academy-bank.json` **على السيرفر فقط**.
- الطالب يحتاج أفضل نتيجة **12/20 أو أكثر في 22 وحدة**، وإرسال كود في **15 TP** حتى يحصل على شهادة إتمام المسار الرقمي.
- الشهادة قابلة للطباعة أو الحفظ PDF من المتصفح، برقم تحقق.
- **الشهادة ليست اعتمادًا رسميًا ولا إثباتًا تلقائيًا لصحة تركيب الدارة**. راجع TP فعليًا عند الأطفال.
- الأستاذ يراجع الكود والـTP بـ«تمّت مراجعة الـTP» أو «يلزم تصحيح».
- إضافة كورسات لاحقًا متاحة من لوحة الأستاذ؛ لا تعطل شهادة Session ESP32 الأصلية.

## 6. مجانية ولا مدفوعة؟

- Render عنده Free Web Service ضمن الحدود: 750 instance-hours / شهر للـWorkspace، وقد يدخل sleep بعد 15 دقيقة بلا استعمال.
- Supabase Free: حد قاعدة بيانات يقارب 500 MB وممكن يوقف المشروع بعد أسبوع من قلة الاستعمال.
- الحسابات والنتائج تبقى في قاعدة البيانات، وليس في ذاكرة Render التي قد تضيع عند restart.
- احفظ backups دورية، ولا تجمع بيانات شخصية غير ضرورية عن الأطفال. خصّص اسمًا دراسيًا أو لقبًا عند الإمكان، وأبلغ الأولياء وسياسة الاحتفاظ.

## 7. ملاحظات تقنية وأمان

- صلاحيات Admin يتم التحقق منها في Node، مش فقط في صفحة الويب.
- `SUPABASE_SECRET_KEY` يبقى في Render server-side فقط. RLS مفعّل على جداول CFI بدون public policies.
- Passwords hashed with `scrypt` salted. Sessions signed with HMAC SHA-256 in HttpOnly cookies.
- لا توجد Public Signup للأطفال؛ الحسابات يعملها الأستاذ يدويًا.
- ينبغي إجراء مراجعة أمنية ونسخ احتياطي وسياسة موافقة الأولياء قبل التوسع التجاري أو تخزين بيانات حساسة.
- إذا فقدت كلمة مرور الأستاذ بعد تغييرها، لا تخلق Admin ثاني بتغيير الاسم في Render. يلزم إجراءات استرجاع مدروسة من مالك قاعدة البيانات.

**CFI** · نسخة V3 تجريبية قابلة للتوسّع، مازالت تحتاج تفعيل قاعدة البيانات على حسابك لتصبح حسابات حقيقية Live.

## تنبيه إضافي على GitHub Public
مستودعك الحالي في GitHub ظاهر **Public**. ما تحطّش فيه كلمات السرّ أو أي Secret Key. للحماية من نسخ الإجابات أو الكورسات الأصلية، من الأفضل تبدّل المستودع إلى **Private** قبل الاستعمال الحقيقي، مع التأكد من منح Render صلاحية الوصول إليه.
